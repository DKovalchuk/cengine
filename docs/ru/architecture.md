## Карта слоёв

```
Python (ctypes)                    Ядро C11
─────────────────                  ─────────────────────────────
cengine/bindings.py  ── FFI ──►    core/       тензор, пул памяти
cengine/module.py                │   math/      AVX2-ядра
cengine/trainer.py               │   nn/        слои, рекуррент
cengine/config.py                │   autograd/  лента, backward
cengine/telemetry.py             │   training/  тренер, оптимизаторы
                                 │   data/      генератор ALU, курикулум
                                 │   parallel/  threadpool, барьеры
                                 │   telemetry/ счётчики, репортёр
```

`cengine/bindings.py` — единственная источник истины на границе FFI: каждая
публичная C-структура зеркалится в `ctypes.Structure` с явной раскладкой
паддингов, каждая функция получает явные `argtypes`/`restype` (потерянный
64-битный `argtype` молча усекает seed'ы — тесты это пинят).

## Тензоры и память

- Выровненные на 64 байта аллокации через центральный пул с трекером
  памяти (`ce_tracker_get_stats` питает метрики `mem_*`).
- `refcount` на каждом тензоре: `ce_tensor_list_append` делает retain,
  уничтожение списка — release. Контейнеры опираются на это: `Sequential`
  выставляет тензоры детей в собственный список параметров (с retain), а
  списки уничтожаются ПОСЛЕ детей — владение сбалансировано.

## Слои и контейнеры

Каждый слой реализует указатели `forward` / `backward` на `ce_module_t`.
Контейнер `Sequential` соединяет детей по порядку (forward) и в обратном
порядке (backward), выделяя промежуточные буферы по ширинам выхода/входа
ребёнка (KAN-слой в середине цепочки раньше получал буфер входной ширины —
теперь ширины берутся из структуры слоя).

Доступ к параметрам двоякий:

- **Листовые модули** владеют своими списками `parameters` / `gradients`.
- **Контейнеры** выставляют плоский родительский список, регистрируемый в
  `ce_sequential_add`, поэтому универсальные потребители
  `ce_module_param_count` (сохранение/загрузка чекпоинтов, C-тренер)
  видят всю модель. Python `Module._collect_params` читает родительские
  списки только у листьев — дублей не возникает.

## Autograd-лента

Лента записывает `(output, grad, backward_fn, state, state_free)` и
проигрывает их в обратном порядке. Состояния слоёв освобождаются через
деструктор `state_free`, записанный на каждую запись (иначе retain-нутые
тензоры текут после `clear`/`destroy`). Одиночные и пустые записи
поддерживаются; **мульти-записные цепочки отклоняются с
`CE_ERR_NOT_IMPLEMENTED`** — полноценная лента-цепочка отложена как
пост-релизная фича; отказ лучше молча неверных градиентов.

## Конвейер данных

```
Генератор ALU ──► prefetch-воркер dataloader ──► готовый батч
      ▲                    (pthread)
      └── ce_dataloader_reseed() присоединяет воркер, применяет новый
          seed/фильтр ops, отбрасывает устаревшие батчи, перезапускает префетч
```

- Генератор производит битовые ALU-сэмплы (ADD/SUB/AND/XOR/OR) с 3-float
  двоичным `op_code` (`op & 1`, `(op >> 1) & 1`, `(op >> 2) & 1`).
- Курикулум расширяет диапазон бит и набор операций по мере падения loss.
- На границе эпох поток пересеивается для перемешивания. Поскольку
  генератор разделяется с prefetch-потоком, каждая переконфигурация идёт
  через `ce_dataloader_reseed()`, который сначала присоединяет воркер —
  прямая запись полей была гонкой (закреплено тестом, сканирующим
  исходники тренера).

## Раскладка батчей

Строки якорятся на **модельных** ширинах (зеркало C
`ce_trainer_prepare_batch`):

```
input  = [a_bits(0..n) | b_bits(anchor..) | op_code(2*anchor..+3)]
             anchor  = (max_input_dim - 3) // 2
target = [result_bits(0..n) | carry_bits(t_anchor..)]
             t_anchor = max_target_dim // 2
mask   = 1.0 на валидных позициях result/carry, 0.0 на паддинге
```

Якорь по ширине батча сдвигал колонки, когда батч был уже модели (код
операции попадал в колонки b-бит); на этот регресс есть отдельный тест.

## Потоки

- **OpenMP** для батч-параллельных ядер; `-fopenmp` при сборке.
- **Prefetch-воркер** (один pthread на dataloader) держит генерацию данных
  вне цикла обучения.
- **Threadpool** для графов задач: shutdown выставляет флаг и рассылает
  broadcast под локом очереди — потерянный wakeup там был гонкой
  (доказана и исправлена под ThreadSanitizer отдельной
  `-fsanitize=thread`-сборкой).

## Телеметрия

```
collector ──► SPSC-кольцо (4096 × 48-байт записей) ──► TelemetryMonitor
   │            (тайминги эпох/forward/backward/оптимизатора,     │
   │             loss, grad norm, память, стадия курикулума …)     └── poll() наполняет
   └── репортёр собирает плоские снапшоты                          историю в Python
```

Кольцо принадлежит Python (ctypes-структура), поэтому `poll()` остаётся
валидным после teardown тренера; `export_csv()`/`export_json()` пишут
только то, что накопил `poll()`.

## Сборка и CI

- `Makefile` автоматически находит исходники; `-O3 -march=native -mavx2
  -mfma` (переносимая сборка без AVX2 в планах).
- CI (GitHub Actions): `make` → `make test` → `pytest tests/ -q` →
  smoke-пакетирования (`pip install .` в чистый venv + импорт извне
  репозитория).
- Набор тестов пинит сквозные свойства: детерминизм (никакой глобальной
  np.random), навигацию документации (каждая локальная ссылка
  разрешается) и запуск каждого примера от начала до конца.
